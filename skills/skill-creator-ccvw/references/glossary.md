# Glossary — skill-creator-ccvw

See also: [`ccvw-glossary.md`](./ccvw-glossary.md) in this same directory for all CCVW shared terms (cluster, FIX, STRENGTHEN, in-flight marker, Round, Phase, ledger, cold-trace, tier, etc.). This file lists ONLY terms specific to skill-creator-ccvw.

## Skill-specific terms

| Term | Definition |
|---|---|
| **adapt path** | Decide Path 3: taking part of another skill with its licence checked, an attribution category (B or C, or A when structure is copied) chosen, and the source recorded in HISTORY.md. |
| **aggregate benchmark** | The summary metrics computed across a single iteration's eval runs by `scripts/aggregate_benchmark.py` — pass rate, per-assertion success, latency, token-cost, variance. Written to `benchmark.json` / `benchmark.md` and shown in the eval viewer's Benchmark tab. |
| **allowed-tools** | The frontmatter field listing the tools a skill may use; CCVW requires it on every skill, defaulting to `["Read"]` for read-only skills. |
| **assertion** | A quantitative check on an eval output (e.g., "the file contains line X", "the JSON has field Y", "the output is under N tokens"). Authored in `evals/evals.json` under the `expectations` field (the single source); the grader evaluates each and records the verdict in `grading.json`. |
| **attribution_lint** | The script `scripts/attribution_lint.py`, which validates the HISTORY.md author, history and inspiration entries that are present and infers the category from the file's shape when the explicit category field is missing or not A, B, C or D (`references/lint-details.md`); it exits 1 on a blocking violation, or when HISTORY.md is missing (then printing only `error` and `note` keys). |
| **author-not-dict** | The blocking `attribution_lint.py` violation raised when HISTORY.md's `author` field is not a mapping; it appears whether or not `declared_category` is `unknown` (`references/lint-details.md`). |
| **AUTHOR-NOT-SET** | The marker an eval worker writes in each field that holds the author's own name (`author.primary` and the fork-adapter name in HISTORY.md, `created-by`, the author's LICENSE copyright line) when its task names no author identity; the orchestrator replaces it from `author_identity` afterwards, only where the marker remains (SKILL.md "Hard rules" rule that begins "Dispatch every eval helper"). |
| **author_identity** | The profile key (environment variable `CCVW_AUTHOR`) holding the user's attribution identity, usually their GitHub login. How it is used: SKILL.md "Step 3 — Author identity". |
| **baseline run** | The eval run WITHOUT the skill (or with a prior version of the skill, when improving an existing one). Compared against the with-skill run to measure the skill's contribution. |
| **baseline_source** | The optional `--var` value for the baseline dispatch template that names the skill snapshot an improve-mode baseline works from; empty in create mode (`references/eval-run-procedure.md` Step 1 (Spawn each test case's runs), Baseline run). |
| **best_description** | The description from the iteration with the best held-out test score (train score when there is no held-out set), which is the one to apply to SKILL.md. |
| **best_score** | The best iteration's score as `passed/total`, on the held-out test set when one exists and on the train set otherwise. |
| **best_test_score** | The best iteration's held-out test score as `passed/total`, or null when no held-out set was used. |
| **best_train_score** | The best iteration's train-set score as `passed/total`. |
| **blocks_tier** | The field on each `portability_lint.py` finding naming the tier or tiers the finding blocks (for example `model-agnostic`, `claude-users and model-agnostic`, `all (...)`, or `none (advisory ...)`). |
| **ccvw_mandatory_missing** | The `portability_lint.py` JSON key listing missing mandatory files, directories and frontmatter fields; any entry blocks every tier (`references/lint-details.md`). |
| **changes-summary** | The `author.history[]` field of a Category A adapter entry holding a one-line summary of what the fork changed (`references/history-template.md`). |
| **Check every baseline** | The bold lead-in of the SKILL.md "Running and evaluating test cases" step that runs the isolation check on each baseline run; exit codes: `references/eval-run-procedure.md` Step 1 (Spawn each test case's runs). |
| **check_set** | The field of an entry in this skill's own `evals/evals.json` naming the set of scripted checks `evals/graders.py` runs for it (`references/schemas.md` "evals.json"). |
| **checked-marketplace:** | The plain-text line under HISTORY.md's Lineage notes heading recording when the marketplace check ran; absent when the check did not run. |
| **claude-users** | One of the three tier values; defined in `references/ccvw-glossary.md` (`tier`). |
| **clean_pass** | The loop-until-dry stop reason `scripts/loop_ledger.py` prints when a round reported no findings; findings left open from earlier rounds do not block it (SKILL.md "Loop-until-dry (opt-in)"). |
| **comparison_result_path** | The analyzer brief's Mode A input naming the comparator's result file for the A-versus-B comparison being explained. |
| **compatibility-length** | The portability_lint finding type raised when the compatibility frontmatter field is not 1 to 500 characters. |
| **compute_would_fail_at** | The `portability_lint.py` function that builds `would_fail_at_tiers`: it adds a tier whenever a finding's `blocks_tier` contains its name, `(warning)` suffix included, so the array alone does not show a real block (`references/lint-details.md`). |
| **copy_fixture** | The field of an entry in this skill's own `evals/evals.json` naming a fixture folder that the orchestrator copies into the skill_out folder before dispatch, so the worker edits the copy. |
| **created-by** | The SKILL.md frontmatter `metadata` key naming the skill's author identity. What it holds: `references/skill-structure-spec.md`; its exemption from the no-identities rule: the SKILL.md "Hard rules" rule that begins "Nothing personal in a skill". |
| **declared_category** | The attribution category (A, B, C, D or unknown) that `attribution_lint.py` reports for a skill, read from HISTORY.md or inferred from its shape. |
| **description-too-long** | The portability_lint finding type raised when the description frontmatter field exceeds 1024 characters. |
| **disable-model-invocation** | One of the Claude-specific frontmatter fields (with user-invocable, context, agent and paths) that the model-agnostic tier forbids; this skill's quick_validate gate rejects all of them at every tier (`references/lint-details.md`). |
| **duration_ms** | The harness's run duration in milliseconds, captured with `total_tokens` at task completion and written with `scripts/write_timing.py`; `aggregate_benchmark` reads `total_duration_seconds` instead (`references/eval-run-procedure.md` Step 3 (As runs complete, capture timing data)). |
| **eval iteration** | One pass of the iterate loop: design → run eval cases → review results → revise skill. Numbered (`iteration-1`, `iteration-2`, …) under `<workspace>`, the configured eval_workspace folder plus the skill name (see the eval_workspace row below and SKILL.md "Personal settings"). |
| **eval-viewer** | The HTML rendering subsystem at `~/.claude/skills/skill-creator-ccvw/eval-viewer/`. Generates an interactive review page from the iteration's eval outputs, now with a sidebar showing Claude-authored recommendations for the next iteration. |
| **eval_feedback** | The optional `grading.json` key holding the grader's critique of the assertions; the recommendations payload draws on it (`references/schemas.md` "grading.json"). |
| **eval_id** | The integer identifying one eval, stored in `eval_metadata.json` and matching the `id` field of its entry in `evals.json`. |
| **eval_name** | The descriptive name of one eval, stored in `eval_metadata.json` and used for its `eval-<descriptive-name>/` directory. |
| **eval_workspace** | The profile key (environment variable `CCVW_EVAL_WORKSPACE`) naming the folder that holds every skill's eval workspace; `<workspace>` is this folder plus the skill name. Default and resolution order: SKILL.md "Personal settings". |
| **evals[].name** | The optional `evals.json` field giving an eval its descriptive name for the `eval-<name>/` folder; a lowercase slug of at most 61 characters (`references/schemas.md` "evals.json"). |
| **execution_metrics** | The `grading.json` key holding tool usage and output size, copied from the executor's `metrics.json`; its `output_chars` stands in for a zero `total_tokens` (`references/schemas.md` "grading.json"). |
| **exit_reason** | The string `run_loop.py` stores in `results.json` saying why the description-optimization loop stopped (`unknown`, `all_passed (iteration N)`, `max_iterations (N)` or `improve_description crashed on iteration N: <error>`). |
| **final_description** | The last description the optimization loop tried, which is not necessarily the best one. |
| **fork-adapter** | The `role` value of a Category A `author.history[]` entry for the person who adapted a fork; its `name` is that person's author identity (`references/history-template.md`, `references/attribution-spec.md`). |
| **frontmatter-angle-bracket** | The portability_lint finding type raised for XML-tag-shaped content anywhere in frontmatter. |
| **heavy-revision** | One of the three allowed `role` values of an `author.history[]` entry (with `original` and `fork-adapter`); the set is closed (`references/attribution-spec.md`). |
| **helper_model** | The profile key (environment variable `CCVW_HELPER_MODEL`) naming the model dispatched helpers run on, and the `--var` value every dispatch template takes for it. Its rule: the SKILL.md "Hard rules" rule that begins "Dispatch every eval helper". |
| **history-entry-invalid-role** | The blocking `attribution_lint.py` violation raised when an `author.history[]` entry's `role` is not one of original, fork-adapter or heavy-revision (`references/attribution-spec.md` "Author and history (used for Category A skills)"). |
| **in_progress** | The task status of the parent task or iteration subtask being worked on; on re-entry it marks where to resume (`references/build-planning.md`). |
| **intended-audience** | The SKILL.md frontmatter `metadata` key holding the same value as `tier`; default `claude-users` (`references/skill-structure-spec.md`). |
| **Intent answers feed README.md + frontmatter** | The bold lead-in of the `references/intent-and-decide-details.md` paragraph mapping each Capture-Intent answer to the README.md section or frontmatter field it fills. |
| **intent_words** | The field of an entry in this skill's own `evals/evals.json` listing words the built skill's README Intent section must contain; each is passed to `evals/graders.py` as `--intent-word`. |
| **isolation check** | `scripts/check_isolation.py`: greps a baseline transcript for the skill name, `SKILL.md` and `/skills/` paths; exit 1 (contaminated) or 2 (no transcript) means discard and re-dispatch, capped at 3 failures. |
| **iterate loop** | The cycle that runs while a skill is being designed and refined: scaffold → eval → review → revise. Distinct from the trace loop (which is skill-tracer's job) — iterate produces a draft, trace audits the draft. |
| **iteration-N** | A placeholder for the literal current-iteration folder `<workspace>/iteration-<number>`; the number is substituted before any command is run (`references/eval-run-procedure.md` Step 4 (Grade, aggregate, and launch the viewer)). |
| **iteration_dir** | One iteration's folder, `<workspace>/iteration-N`, passed to `scripts/render_prompt.py` as a `--var` value for the analyst dispatch template (`references/eval-run-procedure.md` Step 1 (Spawn each test case's runs)). |
| **iterations_run** | The number of iterations the description-optimization loop completed, stored in `results.json`. |
| **loop-until-dry** | Evaluate-and-improve repeated until a full pass finds nothing new, capped at 3 rounds, tracked by `scripts/loop_ledger.py` with stop reasons `clean_pass`, `cap`, `no_progress`. |
| **loser_skill_path** | The analyzer brief's Mode A input naming the skill version that lost the blind comparison. |
| **loser_transcript_path** | The analyzer brief's Mode A input naming the transcript of the run that lost the blind comparison. |
| **marketplace-discover** | The sibling skill that checks the marketplace before a build; defined in `references/ccvw-glossary.md`. |
| **missing-primary-author** | The blocking `attribution_lint.py` violation emitted when HISTORY.md has no `author.primary`. |
| **model-agnostic** | One of the three tier values; defined in `references/ccvw-glossary.md` (`tier`). |
| **name-folder-mismatch** | The portability_lint finding type raised when the name field differs from the skill folder basename. |
| **name-format** | The portability_lint finding type raised when the name field is not kebab-case. |
| **new_skill** | An accepted alias of with_skill for the improved version in improve-mode; the treatment side that `aggregate_benchmark.py` and the viewer recognize (the improve-mode procedure passes with_skill with old_skill: `references/eval-run-procedure.md` Step 1 (Spawn each test case's runs)). |
| **no_progress** | The loop-until-dry stop reason printed when two rounds hold the same non-empty open set and the later one reported nothing new or regressed (SKILL.md "Loop-until-dry (opt-in)", `scripts/loop_ledger.py`). |
| **old_skill** | A config directory name for the baseline version in improve-mode; the baseline side that `aggregate_benchmark.py` and the viewer recognize. |
| **original_description** | The skill's description at the start of an optimization run, stored in `results.json`. |
| **output_path** | The input telling a helper agent which file to write its result to. For the analyzer it depends on the mode: Mode A (blind-comparison analysis) writes its analysis object to whatever path the orchestrator chose; only Mode B (benchmark analyst pass) writes `<workspace>/iteration-N/analyst-notes.json` (`agents/analyzer.md`, `references/schemas.md`). |
| **outputs_dir** | The grader input naming the run's `outputs/` folder; the grader derives the run folder, and so the `grading.json` and `timing.json` paths, from its parent (`references/eval-run-procedure.md` Step 4 (Grade, aggregate, and launch the viewer)). |
| **outputs_wanted** | The `--var` value for the with_skill and baseline dispatch templates saying what the run must produce: the eval entry's expected output, or for this skill's own evals the output folder the prompt names (`references/eval-run-procedure.md` Step 1 (Spawn each test case's runs)). |
| **parent-version** | The version a skill descended from (`null` for a fresh skill): a HISTORY.md frontmatter key, repeated under SKILL.md frontmatter `metadata` for at-a-glance visibility, with HISTORY.md the authoritative copy (`references/skill-structure-spec.md`). |
| **pass_rate** | The fraction of expectations that passed, in the `grading.json` `summary` and in each `benchmark.json` run `result`; `run_summary` gives its mean, stddev, min and max per configuration (`references/schemas.md`). |
| **Path 1, install** | The bold lead-in of the SKILL.md Decide step for a strong marketplace match the user chooses to install: run `marketplace-discover`'s install step and stop. |
| **Path 2, improve** | The bold lead-in of the SKILL.md Decide step for evolving an installed skill; it hands over to `references/improve-existing-skill.md`. |
| **Path 3, adapt** | The bold lead-in of the SKILL.md Decide step for taking part of someone else's skill or pattern with licence and attribution; it then continues as a build (see the adapt path row above). |
| **Path 4, build** | The bold lead-in of the SKILL.md Decide step for everything else, building a new skill; a weak match pauses for the user's go-ahead first (`references/intent-and-decide-details.md`). |
| **persona** | The field of an entry in this skill's own `evals/evals.json` listing the strings (a fictional name, email or home folder in the task) that must not appear in the built skill; each is passed to `evals/graders.py` as `--persona`. |
| **pilot** | The single eval built and run first with `eval_workspace.py --only` before a batch is dispatched. |
| **portability_lint** | The script scripts/portability_lint.py, which checks a skill against the CCVW structure and tier portability rules and emits JSON findings. |
| **portable mode** | Skill-creator-ccvw's tier declaration that triggers `portability_lint.py` to enforce the corresponding tier's portability rules — pass via `--tier claude-users` or `--tier model-agnostic` to `portability_lint.py`. At the opt-in `personal` tier (new builds default to `claude-users`) the lint emits no tier-conditional findings; CCVW-mandatory and structural findings still block (`references/lint-details.md`). |
| **present_files** | A tool some runtimes provide for handing a file to the user; its presence decides whether a built skill is packaged (`references/package-and-present.md`). |
| **productivity:memory-management** | The optional skill that can hold values captured early in the workflow (the deterministic-steps checklist, the marketplace timestamp) across a context boundary, in addition to the visible lines in the response (`references/intent-and-decide-details.md`). |
| **productivity:task-management** | The optional skill whose TASKS.md holds the build's task tree; when it is not installed a plain `build-plan.md` in the workspace holds the same tree (`references/build-planning.md`). |
| **profile** | The markdown file of per-user settings (`config/user-profile.md` or `$CCVW_USER_PROFILE`) that `scripts/skill_config.py` reads; nothing personal is written into the skill. |
| **Public domain / CC0** | The bold lead-in of the `references/attribution-spec.md` licence bullet for a public-domain original: no terms to preserve, but the lint still expects a LICENSE file when a history chain is recorded. |
| **quick_validate** | The frontmatter-gate lint of this skill, `scripts/quick_validate.py`: plain-text output, judged by its exit code alone (`references/lint-details.md`). |
| **recommendations payload** | The `recommendations.md` file the orchestrator authors after each eval iteration. Required structure: "What this iteration did well" (≥2 bullets) / "What this iteration failed at" (≥2) / "Recommended next iteration" (≥3) — counts are minimums, not maximums. Rendered as a sidebar in the session report HTML. |
| **regressed** | A finding in the loop ledger that was marked resolved and was reported again in a later round. |
| **reserved-name** | The portability_lint finding type raised when the name is claude or anthropic, or starts with one followed by a hyphen or underscore. |
| **run_dir** | One run's folder, `<workspace>/iteration-N/eval-<name>/<config>/run-1`, passed to `scripts/render_prompt.py` as a `--var` value for the with_skill and baseline dispatch templates (`references/eval-run-procedure.md` Step 1 (Spawn each test case's runs)). |
| **run_loop** | The description-optimisation script `scripts/run_loop.py`; it scores trigger queries on a train and a held-out test split and writes `results.json` (`references/description-optimization.md`, `references/schemas.md` "results.json"). |
| **Running test cases without subagents** | The bold lead-in of the `references/runtime-adaptations.md` paragraph on the Claude.ai runtime, where the orchestrator follows the skill itself, one test case at a time, instead of dispatching runs. |
| **runs_per_configuration** | The `benchmark.json` metadata field giving the number of runs each eval has per configuration: the largest run count of any one eval for any configuration, not the total across evals (`references/eval-run-procedure.md` Step 4 (Grade, aggregate, and launch the viewer)). |
| **scaffold** | The set of files and directories skill-creator-ccvw creates when initializing a new skill. CCVW scaffold includes mandatory frontmatter, mandatory dirs, and `references/glossary.md` from the shared template. |
| **scratch_dir** | The profile key (environment variable `CCVW_SCRATCH_DIR`) naming the folder for temporary files, and the `--var` value every dispatch template takes for it. What to do when it is empty: SKILL.md "Personal settings". |
| **Server mode (default)** | The bold lead-in of the `references/eval-run-procedure.md` viewer-launch note for the default local-server run, as opposed to the static single-file report. |
| **session_log_dir** | The profile key (environment variable `CCVW_SESSION_LOG_DIR`) naming the folder for the iteration-start session-log line; empty or `off` means no logging (SKILL.md "Personal settings", `references/eval-run-procedure.md` Step 1 (Spawn each test case's runs)). |
| **skill-md-misnamed** | The portability_lint finding type raised when the main file is not named exactly SKILL.md. |
| **skill-publisher** | The sibling skill that polishes, tier-checks and ships a finished skill; the next phase after tracing (SKILL.md "Suggest the next phase: trace, then ship"). |
| **skill-snapshot** | The `<workspace>/skill-snapshot/` copy of the skill taken once per improve cycle, before the first evolution edit, as the `old_skill` baseline; only improve Step 3 creates or replaces it, setting an earlier one aside as `skill-snapshot-old-<n>` (`references/improve-existing-skill.md` Step 3 (Draft changes preserving intent)). |
| **skill_creator_path** | The `--var` value for the grader and analyst dispatch templates naming this skill's own install directory, the folder holding its SKILL.md and `agents/`. |
| **skill_name** | The `evals.json` key (also a `benchmark.json` metadata key) naming the skill, matching its frontmatter `name` (`references/schemas.md`). |
| **skill_out** | The placeholder in this skill's own eval prompts for the folder, inside the run's folder, where the worker saves the built skill; the orchestrator fills it in before rendering the prompt (`references/schemas.md` "evals.json"). |
| **skill_path** | The input naming the directory of the skill being analysed or linted; for a new build, the folder created at "Write the three root files" in SKILL.md (the user's chosen location, else a folder named after the skill under the working directory). |
| **target skill** | The skill being built or improved — distinct from skill-creator-ccvw itself (the meta-skill orchestrating the build). |
| **task-management integration** | The task tree (via `productivity:task-management` when installed, else a plain plan file) that maintains a parent task ("Build skill X") with iteration child subtasks in TASKS.md, persisting state across sessions so re-entering shows the full build state without opening the workspace. |
| **test_size** | The number of eval queries held out as the test set in an optimization run. |
| **tier flag** | Command-line argument `--tier <value>` for `portability_lint.py`, where value is `personal`, `claude-users`, or `model-agnostic`. Drives the portability_lint.py rule set applied. Note: this is optional — the script reads `metadata.tier` from SKILL.md when `--tier` is omitted; pass `--tier` only to test hypothetical tier compatibility. |
| **tier_violations** | The `portability_lint.py` JSON key listing every structural, frontmatter-content, tier-portability, personalization and advisory finding, each with its `blocks_tier`; how to read it and what blocks which tier: `references/lint-details.md`. |
| **time_seconds** | The `benchmark.json` run `result` and `run_summary` field for run time; `aggregate_benchmark` takes it from `grading.json` first (executor plus grader) and `timing.json` second (executor only), so its meaning can differ between runs (`references/eval-run-procedure.md` Step 3 (As runs complete, capture timing data)). |
| **Timeouts** | The bold lead-in of the `references/runtime-adaptations.md` Cowork paragraph on running test prompts in series when Cowork times out. |
| **tmp-cleanup-advisory** | The advisory portability_lint finding type raised when the SKILL.md body names a `/tmp/` path and no cleanup text appears anywhere in it; its `blocks_tier` starts with `none`, so it never blocks a tier. |
| **tool_calls** | In `metrics.json` and `grading.json` `execution_metrics`, the count of calls per tool type; in a `benchmark.json` run `result`, a single total (`references/schemas.md`). |
| **total_duration_seconds** | The wall-clock seconds key in `timing.json` and in the `grading.json` `timing` block, the one `aggregate_benchmark` reads for duration (`references/schemas.md`). |
| **total_tokens** | The `timing.json` key holding the harness's token count for a run, captured from the task-completion notice and written with `scripts/write_timing.py`; a zero is replaced by `output_chars` (`references/eval-run-procedure.md` Step 3 (As runs complete, capture timing data)). |
| **train_size** | The number of eval queries used as the train set in an optimization run. |
| **transcript_path** | The grader input naming the `transcript.md` the run wrote in its `run-1/` folder (`references/eval-run-procedure.md` Step 4 (Grade, aggregate, and launch the viewer)). |
| **trigger-eval set** | A JSON file listing natural-language queries that should, and near-miss queries that should not, activate the skill (`references/description-optimization.md` Step 1). Used to score the skill's description's effectiveness at triggering. Stored as `eval_set.json` under `<workspace>/trigger-opt/` (`references/description-optimization.md` "Step 3: Run the optimization loop"). |
| **unknown-tier** | The advisory `portability_lint.py` finding for a `metadata.tier` value outside personal, claude-users and model-agnostic; it never blocks a tier (`references/lint-details.md`). |
| **user_notes_summary** | The `grading.json` key holding the issues the executor flagged (uncertainties, items needing review, workarounds); `aggregate_benchmark` folds it into each run's notes (`references/schemas.md` "grading.json"). |
| **winner_skill_path** | The analyzer brief's Mode A input naming the skill version that won the blind comparison. |
| **winner_transcript_path** | The analyzer brief's Mode A input naming the transcript of the run that won the blind comparison. |
| **with_skill** | A config directory name for runs made with the skill; the treatment side that `aggregate_benchmark.py` and the viewer recognize. |
| **without_skill** | A config directory name for baseline runs made without the skill in create-mode; the baseline side that `aggregate_benchmark.py` and the viewer recognize. |
| **would_fail_at_tiers** | The JSON array `portability_lint.py` emits listing which tiers the skill's current findings would fail at. |
| **YYYY-MM-DDTHH:MM** | The UTC timestamp format written after checked-marketplace: in HISTORY.md, for example 2026-05-31T11:27. |
