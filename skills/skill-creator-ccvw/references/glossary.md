# Glossary — skill-creator-ccvw

See also: [`ccvw-glossary.md`](./ccvw-glossary.md) in this same directory for all CCVW shared terms (cluster, FIX, STRENGTHEN, in-flight marker, Round, Phase, ledger, cold-trace, tier, etc.). This file lists ONLY terms specific to skill-creator-ccvw.

## Skill-specific terms

| Term | Definition |
|---|---|
| **aggregate benchmark** | The summary metrics computed across a single iteration's eval runs by `scripts/aggregate_benchmark.py` — pass rate, per-assertion success, latency, token-cost, variance. Feeds into the session report's "How did this iteration do" panel. |
| **assertion** | A quantitative check on an eval output (e.g., "the file contains line X", "the JSON has field Y", "the output is under N tokens"). Authored in `evals/evals.json` under the `expectations` field (the single source); the grader evaluates each and records the verdict in `grading.json`. |
| **baseline run** | The eval run WITHOUT the skill (or with a prior version of the skill, when improving an existing one). Compared against the with-skill run to measure the skill's contribution. |
| **build-vs-install decision** | The user's explicit choice after marketplace-discover presents candidates — either install one of the recommendations (skill-creator-ccvw exits without building) or proceed with build (recorded in the new skill's HISTORY.md — a `checked-marketplace` line in the Lineage notes). |
| **eval iteration** | One pass of the iterate loop: design → run eval cases → review results → revise skill. Numbered (`iteration-1`, `iteration-2`, …) under `~/.claude/skill-creator-evals-ledger/<skill>/`. |
| **eval-viewer** | The HTML rendering subsystem at `~/.claude/skills/skill-creator-ccvw/eval-viewer/`. Generates an interactive review page from the iteration's eval outputs, now with a sidebar showing Claude-authored recommendations for the next iteration. |
| **iterate loop** | The cycle that runs while a skill is being designed and refined: scaffold → eval → review → revise. Distinct from the trace loop (which is skill-tracer's job) — iterate produces a draft, trace audits the draft. |
| **iteration metadata** | Per-eval `eval_metadata.json` files capturing each test case's `eval_id`, `eval_name`, and `prompt`. Stored at the `eval-<descriptive-name>/` level (e.g. `eval-chart-formatting/` — the descriptive directory name, NOT the integer eval_id; one per eval, shared across its config/run dirs); both `aggregate_benchmark` and the viewer read it from there. |
| **mandatory-scaffold check** | The scaffold logic skill-creator-ccvw runs when creating a new skill — ensures every CCVW skill ships with `license`/`compatibility`/`metadata`/`allowed-tools` frontmatter and `scripts/`/`references/`/`assets/` directories with the required per-skill `references/glossary.md`. |
| **portable mode** | Skill-creator-ccvw's tier declaration that triggers `portability_lint.py` to enforce the corresponding tier's portability rules — pass via `--tier claude-users` or `--tier model-agnostic` to `portability_lint.py`. Personal-tier (default) just runs lint in advisory mode. |
| **recommendations payload** | The `recommendations.md` file the orchestrator authors after each eval iteration. Required structure: "What this iteration did well" (≥2 bullets) / "What this iteration failed at" (≥2) / "Recommended next iteration" (≥3) — counts are minimums, not maximums. Rendered as a sidebar in the session report HTML. |
| **scaffold** | The set of files and directories skill-creator-ccvw creates when initializing a new skill. CCVW scaffold includes mandatory frontmatter, mandatory dirs, and `references/glossary.md` from the shared template. |
| **session report** | The HTML page generated by `eval-viewer/generate_review.py` showing one iteration's eval results plus the Claude-authored recommendations sidebar. Opened in the user's default browser after each iteration. |
| **target skill** | The skill being built or improved — distinct from skill-creator-ccvw itself (the meta-skill orchestrating the build). |
| **task-management integration** | The `productivity:task-management` invocation that maintains a parent task ("Build skill X") with iteration child subtasks in TASKS.md, persisting state across sessions so re-entering shows the full build state without opening the workspace. |
| **tier flag** | Command-line argument `--tier <value>` for `portability_lint.py`, where value is `personal`, `claude-users`, or `model-agnostic`. Drives the portability_lint.py rule set applied. Note: this is optional — the script reads `metadata.tier` from SKILL.md when `--tier` is omitted; pass `--tier` only to test hypothetical tier compatibility. |
| **trigger-eval set** | A JSON file listing the natural-language phrasings that should activate the skill. Used to score the skill's description's effectiveness at triggering. Stored as `trigger-eval*.json` under the skill's eval workspace. |
