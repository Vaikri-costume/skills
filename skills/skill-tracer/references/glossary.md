# Glossary — skill-tracer

See also: [`~/.claude/skills/skill-creator-ccvw/references/ccvw-glossary.md`](../../skill-creator-ccvw/references/ccvw-glossary.md) for all CCVW shared terms (cluster, FIX, STRENGTHEN, in-flight marker, Round, Phase, ledger, cold-trace, tier, etc.). This file lists ONLY terms specific to skill-tracer.

## Skill-specific terms

| Term | Definition |
|---|---|
| **action keyword** | The third whitespace-separated field of an in-flight marker, indicating what state the prior session was in when it left the marker. Three distinct values: `dispatch` (mid-Step-4-dispatch interrupted), `addressing` (mid-Step-6-addressing interrupted), `handoff` (clean end-of-round signal). Never overloaded — each keyword has exactly one meaning. |
| **adversarial verify** | The cold-parallel dispatch pattern shared with deep-research and pr-review-toolkit: independent agents commit to claims before seeing peers' findings; the orchestrator reconciles. Structural enforcement of independent perspective. |
| **agent-description string** | The exact string set as the Agent tool's `description` parameter at dispatch. Three — one per cold direction: `Forward trace of <skill>`, `Backward trace of <skill>`, `Executor trace of <skill>`. This list is closed. Load-bearing because Step 1(a)'s session-JSONL recovery scans for these strings to recover tool_use IDs. |
| **`<dispatch-set>`** | In-memory variable holding the directions this round will dispatch — always the constant `[forward, backward, executor]` (skill-tracer is correctness-only; no cadenced or override-flag variation). Drives Step 3 prompt building + the three Agent calls in the same-turn dispatch. |
| **backward trace** | Reads from each producer (script print/exit, brief output format) back to the consumers (SKILL.md steps that read those values). Defined in `references/backward.md`. |
| **bias toward FIX** | Step 6's controlling rule: FIX is the default address for every cluster. STRENGTHEN is the narrow exception only when the artifact is correct and the cluster reflects intent the trace agents couldn't see. |
| **cluster grouping procedure** | Step 5's three-test procedure for deciding whether two flags belong to the same cluster: same Claim text anchor, same fix would close both, or same root cause across symptoms. When in doubt, keep separate. The Claim-text-anchor test is **same-round only** (verbatim `Claim:` quotes live in each round's agent reports, not the ledger); the durable cross-round key is Root cause — see "regression vs cascade". |
| **cold dispatch** | An Agent call issued without any awareness of sibling agents, prior fix history, or convergence-round mentions. Each trace agent's prompt is self-contained — no orchestrator state leaks in. |
| **considered-fix invariant** | The orchestrator weighs each ISSUE against the target skill's documented intent before applying a fix. Random "make the tracer happy" fixes are forbidden — they destroy the skill's design. |
| **convergence (Condition A)** | The state at which a skill is deemed traced: all three trace agents (forward, backward, executor) return `No issues found` in one cold round **and no unresolved `USER-PAUSE` cluster remains from any round or phase** (incl. a round-1 `REVIEW`-phase pause). Tested over `TRACE`-phase clusters only — `REVIEW`/`CR*` clusters never block convergence. The authoritative statement is SKILL.md Step 8; this entry is the glossary gloss. skill-tracer is correctness-only — there is no Condition B (that CCVW-compatibility gate moved to skill-publisher). |
| **convergence loop** | The full-convergence mode workflow that runs Steps 3-7 repeatedly until Condition A holds (all three agents clean in one cold round). Default behavior is inline continuation (loop in same session). |
| **executor trace** | Reads SKILL.md line-by-line from the executor's perspective, asking at each line whether the action is unambiguous from text already read. Defined in `references/executor.md`. |
| **forward trace** | Starts from each claim in SKILL.md and works forward to verify the script/file/step the claim points at actually delivers what's claimed. Defined in `references/forward.md`. |
| **fix conservatism** | Step 6's rule: change the minimum text needed to resolve the specific cluster. Whole-section rewrites turn one cluster into many. |
| **inline continuation** | Step 7 default: orchestrator loops in same session through all rounds until convergence. Distinct from self-invoking handoff (which exits between rounds, waits for re-invocation). |
| **invariants (the four)** | Cold-trace, considered-fix, no-orphan-flag, WHY-strengthening. The four orchestrator-side rules that hold across every round of the trace loop. |
| **ISSUE block** | A trace agent's output block: tag in brackets, file path, `Claim:` (exact quote from skill), `Target:` (what file/script/brief actually says/does). |
| **no-orphan-flag invariant** | Every ISSUE raised by a trace agent must be addressed — FIX, STRENGTHEN, or USER-PAUSE — and the address must land inside the skill, not in an external log. |
| **opt-in handoff** | The Step 7 alternative path triggered by explicit user request ("just round N, then stop"). Writes `handoff round-<N+1>` and exits. (The 10-round ask-gate "stop" is a *separate* terminal path that also writes a `handoff` marker but is NOT the opt-in handoff — see SKILL.md Step 7. Compaction-driven mid-round interruption is handled by the atomic-write marker + recovery rules, not by a proactive orchestrator yield.) |
| **PRE-FLIGHT gate** | The first output each trace agent emits — one `PRE-FLIGHT <path>: <line_count> lines, last edited <yyyy-mm-dd>` line per file in the file list (exact format + parser: `references/ledger-format.md` "PRE-FLIGHT drift test" / `ledger_common.PREFLIGHT_RE`). Sanity-checks the file list was reachable AND that on-disk files match what the orchestrator enumerated (mismatch signals concurrent modification). |
| **prompt staging** | Step 4's required step: write all three filled trace prompts to scratchpad files under `/tmp/skill-tracer-prompts/` BEFORE issuing any Agent dispatch (one per direction in `<dispatch-set>`, which is always `[forward, backward, executor]`). Separates prompt composition from same-turn dispatch. |
| **regression vs cascade** | Round-on-round, REGRESSION is a cluster whose Root cause matches one already addressed in a prior round (the prior fix was incomplete). CASCADE is a cluster with an all-new Root cause raised because a prior round's fix opened previously-invisible adjacent gaps (healthy). (Root cause — not verbatim Claim text — is the durable cross-round key, since the ledger persists Root cause; see address-decision.md. Claim-text matching is only for *same-round* cluster grouping.) Convergence checks regression count → 0, NOT raw count → 0. |
| **resume-on-handoff** | Step 1(a) recovery rule 3 behavior: when a `handoff round-N` marker is present, this session overwrites it with `dispatch round-N` and proceeds to Step 3/4 for round N. |
| **same-turn requirement** | Step 4 invariant: all three trace Agent calls MUST be issued in the same assistant message (one per direction in `<dispatch-set>` = `[forward, backward, executor]`). Reading any tool_result before all three are issued breaks the cold-parallel property; recover by re-issuing the dispatch — discard the partial results, keep the `dispatch round-N` marker, and re-issue all three same-turn (per `dispatch-protocol.md`). |
| **single-round mode** | One of three invocation modes (`--one-round`): run exactly one cold round, then stop. Skips the convergence loop-back (the round-on-round re-dispatch); Step 5's substance-failure re-dispatch *within* the single round still runs. Used for diagnostic snapshots. |
| **verify-only mode** | One of three invocation modes (`--verify-only`): run one cold round, produce the ledger with "would-FIX" / "would-STRENGTHEN" / "would-USER-PAUSE" addresses, apply nothing — it previews what a round *would* change without changing it (e.g. to check pending state between user edit sessions). |
| **WHY-strengthening invariant** | When an ISSUE flags a missing WHY for an intentional design decision, the address is to ADD the WHY to the skill, not to remove the rule. The most common operational form of the no-orphan-flag invariant. |
