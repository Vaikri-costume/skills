# Glossary — skill-tracer

This glossary is self-contained: skill-tracer must not depend on `skill-creator-ccvw`'s shared
glossary or any other external file to be understood, so every stable name this skill's own text
coins or relies on is defined here, even where a CCVW-family sibling skill also uses the same
term.

## Skill-specific terms

| Term | Definition |
|---|---|
| **blast_advisory** | The `blast_advisory` array emitted by `code_review_collect.py` — groups of two or more verified flags that share the same lowercased file basename plus first cited line number (reviewer flags carry no token, so `ledger_common.compute_advisory_groups`' shared-token key never applies to them) (with no line cited, the basename plus the target's first 60 lowercased characters; `ledger_common.normalize_loc`), and must therefore be clustered together; flags citing different lines of one function form no group, and flags citing the same line of same-named files in different directories do; the orchestrator MAY merge beyond advisory blast groups but CANNOT split one across clusters |
| **cluster** | A group of one or more verified findings that share a root cause or must be fixed together: for Code Review, written by the orchestrator to `<out-dir>/cr-clusters-<N>-<RUN_TIMESTAMP>.json`; for Prepass, built by `prepass_run.py` through `cluster_prepass.py` with no orchestrator cluster file; in both tiers dispatched in a fixer batch of at most 12 clusters, one fixer agent per batch |
| **Round** | One pass through the 2-tier cascade at the current `<round-number>`; a round closes only once every ledger row opened in it is resolved (no row still PENDING and `check-pauses` exits 0; `close-round` refuses otherwise), and convergence requires a round whose prepass and full-sweep code-review are both clean |
| **Phase** | The cascade tier a given in-flight marker or ledger row belongs to: `prepass` or `code-review` in the marker (`Prepass` or `Code Review` in a row); a legacy `minor-bugs` marker is migrated to `code-review running`. Distinct from a check's `Level`, which names how a detector's findings are used |
| **ledger** | The per-target record at `${XDG_DATA_HOME:-$HOME/.local/share}/skill-tracer-audit-ledger/<basename>.md`, written by the scripts (rows are appended; a script may also fill a PENDING row's Address, drop stale PENDING rows of a re-run pass, and rewrite the single `in-flight::` marker line, but never edits a filled row), that tracks the target it belongs to (a `target:: <absolute target path>` header line written by `begin-round`), the single in-flight marker of the latest round, PENDING/resolved findings, and pause state; the single source of truth an orchestrator re-derives from on every invocation, including post-compaction resume |
| **tier** | One of the cascade's two stages, prepass then code-review, each gating entry to the next; "2-tier cascade" names the whole sequence |
| **ISSUE** | The literal block-opener token (`ISSUE [<tag>]:`) a cold code-review agent emits for each surviving finding, followed by `File:` / `Claim:` / `Target:` lines in the strict four-line contract |
| **USER-PAUSE** | The pause type the orchestrator promotes an ORCHESTRATOR-PAUSE to when genuine user judgment is required and cannot be derived from the target's README `## Intent` or skill files; a round cannot close while a USER-PAUSE remains unresolved |
| **cluster_enforce** | The mandatory script (`scripts/cluster_enforce.py`) that is the ONLY path to writing Code Review PENDING ledger rows and staging the Code Review fixer prompt (Prepass PENDING rows and prompts come from `prepass_run.py`); refuses (exit 1) if any verified flag is dropped or if any advisory blast group is split across clusters — the orchestrator cannot bypass it or hand-write PENDING rows directly |
| **code-review** | The cascade's second tier: two cold Explore-subagent generalists (`G1`, `G2`) read the review scope across all five code-review lenses through the ALLLENS prompt; a clean full-sweep code-review is convergence |
| **Cold-read** | One of the four invariants (SKILL.md "The four invariants"): every code-review agent is dispatched independently (no sibling mentions, no fix-log carry-over, no "what changed" preamble); enforced by `subagent_type: Explore` (no Edit/Write tools) with a post-dispatch edit check as backstop, not by prompt instruction alone. The changed-files scope list is the file list, not a fix log |
| **considered-fix** | One of the four invariants (SKILL.md "The four invariants", named Considered-fix): the orchestrator weighs each finding against the target's documented intent before applying a fix; "make the checker happy" fixes that destroy design are forbidden regardless of round |
| **convergence** | A round in which prepass is `converged` and a full-sweep code-review is `code-review-clean` with every pause resolved; a clean code-review is reachable only after a clean prepass in the same round. A clean changed-files review (`changed-scope-clean`) is never convergence |
| **coverage gate** | The check run by `code_review_collect.py` that verifies each cold reviewer agent read every line of every file in the review scope (the cr-scope record; every in-scope file when it is absent); agents that sampled rather than full-read are sent a `SendMessage` to fill the gap before their findings are accepted |
| **code-review lens** | One of the five review perspectives a code-review agent applies, each with its own body file `prompts/agent-<lens>.md`: fidelity, every claim matches what the referenced scripts, files or steps deliver; executor, each action is unambiguous from text already read; logic, conditional logic, closure intent, whether a WHY is available at its point of use, and cross-step contradictions; integrity, cross-references, inter-script contracts and invariant enforcement are consistent; design, architecture, abstractions and structural choices are sound. A generalist runs all five through the ALLLENS prompt |
| **fill-address** | The `ledger_cascade.py --mode fill-address` step that reads the fixer agents' transcripts (one per batch, all in one call) and writes address decisions into open PENDING ledger rows; called once the round's fixer batches have returned, in both tiers |
| **FORBIDDEN-PAUSE** | The rule that, while a run is in progress, the orchestrator never offers to pause or stop early for "tail issues", "diminishing returns", "minor findings", a long session, round size, cluster count, or token cost. The only legitimate stops are convergence, a round-gate stop, a genuine USER-PAUSE and a hard unrecoverable error |
| **no-drop gate** | The cluster_enforce enforcement rule: every verified flag ID from `code_review_collect.py` must appear in the orchestrator's cluster JSON exactly once, with no flag id the collector did not verify, and every cluster must carry a distinct non-empty id and a non-empty flags list; any omission, extra id, duplicate or malformed cluster causes `cluster_enforce.py` to exit 1 and refuse to stage the fixer |
| **No-orphan-flag** | One of the four invariants (SKILL.md "The four invariants"): every finding is addressed by FIX, STRENGTHEN, or ORCHESTRATOR-PAUSE, and the address must land inside the target — not in an external log; machine-checked by `append_ledger.py close-round`, which refuses to close a round while any of its rows is still PENDING (no address recorded yet) or any of its pauses is unresolved (the open pauses are the ones `append_ledger.py check-pauses` lists) |
| **Fixer model rule** | The rule for choosing each fixer batch's model (`ledger_common.fixer_model`): `opus` for every batch of a tier pass with more than 15 clusters, `sonnet` otherwise. Applies to both tiers. Data: Sonnet introduced regressions at 17 and 28 clusters of mixed work; batches stay at 12 or fewer clusters. A tier pass of 12 or fewer clusters is one batch, so one model covers all its clusters |
| **ORCHESTRATOR-PAUSE** | An address type for a cluster whose intent-preserving fix could not be derived or applied: a fixer emits it when it cannot derive the fix from the target's README `## Intent` or skill files (`references/how-to-fix.md`), `ledger_cascade.py --mode fill-address` assigns it to a cluster with no fixer decision, `prepass_run.py` writes it for a repeat-count auto-pause, and a fixer re-emits it when the post-fix gate's problems remain (SKILL.md "Post-fix gate"); the orchestrator resolves an ORCHESTRATOR-PAUSE by default and promotes to USER-PAUSE ONLY when genuine user attention is truly needed (the one exception: a prepass `auto_pause` entry with `resolutions` of 1 or more is a USER-PAUSE) — promoting to avoid a derivable call is the lazy-pause anti-pattern |
| **prepass** | The cascade's first tier: `prepass_run.py` sweeps the target with the prepass detectors (broken refs, dangling step refs, dead scripts, sub-step labels, CLI flags a doc cites in a `python[3] [<dir>/]<name>.py` invocation or a fenced command that the script does not register, duplicated regexes), clusters the findings and blast-fixes them in-round; re-enters until the script emits `converged` before code-review may begin, each finding signature getting at most 2 fixer passes per round before the repeat-count auto-pause takes it |
| **WHY-strengthening** | One of the four invariants (SKILL.md "The four invariants"): when a finding flags a missing rationale for an intentional design decision, the fix is to add the WHY inside the skill at the point of use — not to remove the rule; the most common operational form of No-orphan-flag |
| **Broken ledger** | The failure mode where the ledger is unreadable or missing at a point where it must exist; the orchestrator stops and tells the user the path and the failure rather than reconstructing or guessing ledger state. One case of a hard unrecoverable error |
| **check-pauses** | The `append_ledger.py check-pauses` subcommand that verifies no open ORCHESTRATOR-PAUSE/USER-PAUSE rows remain in the ledger; a round may only be closed, and code-review only counted CONVERGED, once this exits 0 |
| **verify-auditability** | The `append_ledger.py verify-auditability` subcommand that asserts, for one round, that every expected flag id appears in exactly one ledger row (none dropped, none counted twice); exits 1 on a violation; an optional manual check that no workflow step runs |
| **RUN_TIMESTAMP** | A `<Runtime>` (an ISO-8601 UTC timestamp such as `2026-10-05T10:00:30`) with every `:` replaced by `-`; the form carried in every staged or tmp file name that belongs to one run (`blast-round-<N>-<RUN_TIMESTAMP>.json`, `code-review-ALLLENS-<RUN_TIMESTAMP>.txt`, ...), so `cleanup_tmp_prompts.py --run-timestamp` removes exactly one run's files and accepts either spelling |
| **begin-round** | The `append_ledger.py begin-round` subcommand that starts a round: creates the ledger when absent (recording `--target` on its `target::` line), refuses with exit 2 a ledger whose `target::` line records a different target (two targets with the same basename would otherwise share one ledger), records `--target` on a legacy ledger that has no `target::` line, writes the round's first in-flight marker (`prepass running round-<N>`) and can persist run options with `--set key=value` |
| **needs-fix** | A tier script's status (`prepass_run.py`, `cluster_enforce.py`) meaning findings exist: PENDING ledger rows were written and one fixer prompt per fixer batch was staged (`batches`; batch 1's prompt also as `staged_prompt` / `staged_fixer_prompt`), or, when every cluster was auto-paused, only open ORCHESTRATOR-PAUSE rows were written and no fixer prompt was staged (`auto_pause` alone; resolve each pause, then re-run the tier) |
| **needs-record** | The `prepass_run.py` status meaning a fixer already ran but its decisions were never written into the ledger (Prepass PENDING rows remain although the sweep is now clean): run the fixer's decision check and post-fix gate `check`, then record them with the fix-recording step before Prepass can converge |
| **detector_errors** | The array in `cascade_sweep.py --json` (passed through by `prepass_run.py`) listing every detector that could not load or raised on a file; a non-empty array stops Prepass (`prepass_run.py` exits 1) because a crashed detector proves nothing about the target |
| **intent source** | The file whose text states a target's documented intent: its README.md (`## Intent`), or its SKILL.md (frontmatter `description:`) when it has no README.md; resolved by `ledger_common.intent_source` and handed to the fixer as the `[README]` slot |
| **code-review-clean** | The `code_review_collect.py` status meaning a full-sweep code-review surfaced zero flags; with a `converged` prepass in the same round and no open pause it is convergence |
| **internal-contradiction** | The ISSUE tag used when two passages describing the same procedure or rule are inconsistent across distant sections of a skill (as opposed to a local, same-breath inconsistency between two adjacent lines or steps) |
| **Provenance pointer** | The load-bearing dispatch rule that a cold agent or fixer is pointed at its staged prompt file rather than given the file's text: the dispatch prompt first states the agent's role and output contract in the orchestrator's own voice, then frames the file as data generated by this same orchestrating session. A bare "read this file and follow it" pointer reads as prompt injection and gets refused; inlining the text defeats staging |
| **Explore trade-off** | The documented limitation of `subagent_type: Explore` read-only agents: they tend to sample rather than full-read files and to drift from the exact ISSUE four-line form. The read-coverage gate and contract recovery handle both; the agent type is never changed away from Explore, because read-only must be enforced by the tool list |
| **Level** | A detector's role, from its module's `LEVEL` constant: `prepass` (its findings gate the Prepass tier) or `advisory` (reported by `doc_lint.py`, never gating); `cascade_sweep.py --level` selects one |
| **subagent_type** | The dispatch parameter that selects which agent type an orchestrator step spawns (`general-purpose` for the edit-capable fixer, `Explore` for read-only code-review agents); changing it away from the documented value breaks the structural read-only enforcement |
| **verified-flags** | The `code_review_collect.py` status reached once every cold reviewer's output passed the contract and coverage checks and the surviving findings were numbered as flags; the orchestrator clusters them next, and convergence is only reached via a later clean full-sweep code-review |
| **FIX** | The default address type: the artifact itself is changed so a defect no longer exists — the fixer's action is recorded as `FIX (<file>: <summary>)` in the ledger row's Address column |
| **STRENGTHEN** | The narrow-exception address type: the underlying artifact is already correct and only a missing WHY/closure-marker/pointer/edge-case note is added — recorded as `STRENGTHEN (added at <file>:<lines>: "...")` in the ledger row's Address column |
| **touched_files** | The JSON array field of a fixer's decision object, listing every file a FIX or STRENGTHEN actually edited — required for fix-impact-closure verification |
| **In-flight marker** | The single ledger-header line of the form `in-flight:: <Runtime> <phase> <state> round-<N>` that records which phase/state/round is currently running, so a resumed session re-derives progress from disk instead of from memory |
| **stale-sibling** | The post-fix gate problem kind for a file, flag or defined name the fix removed that the new tree still names somewhere (`post_fix_gate.py`); the fixer closes it with `check_fix_radius.py` on the removed name |
| **repeat-count auto-pause** | The loop-safety behaviour of `prepass_run.py` (a shared helper in `ledger_common.py`): a cluster whose signature (check, file; the handler-shape part is reserved and unused, `cluster_prepass.py`) already has two addressed Prepass rows this round is written as an open ORCHESTRATOR-PAUSE row, left out of the staged fixer prompt and listed under `auto_pause`; when every cluster is paused, no fixer prompt is staged. A cluster addressed once is still sent to the fixer, annotated with its `repeat_count` so the fixer moves up a rung. This counter is the bound on the prepass fix loop (SKILL.md "Retry bound"); a resolving row restarts a signature's count, so a resolved finding is fixed again before it can be auto-paused again, and an auto-pause with `resolutions` of 1 or more (it came back after a resolved pause) is a USER-PAUSE, which bounds the loop; otherwise a pause is promoted to USER-PAUSE only when the intent is not derivable |
| **Contract recovery** | The recovery path when a cold agent's output violates the strict output contract (malformed or incomplete block, wrong trailing line, a block count other than the declared count, insufficient read coverage): `SendMessage` that same agent to reformat or read the gap and re-emit, rather than starting a fresh cold agent |
| **VALID_STATES** | The `scripts/ledger_common.py` constant enumerating the legal in-flight-marker `<state>` values (`running` / `addressing` / `dispatched` / `orch-fixes`); the source of truth if the prose list in `references/recovery.md` ("In-flight marker") and the code disagree |
| **Reading procedure** | `prompts/agent-executor.md`'s two-pass reading methodology for a dispatched executor agent: a first pass to build the full picture, then a second pass to verify claims against the literal text before writing any finding |
| **Promotion rule (orchestrator layer)** | `how-to-fix.md`'s rule that the orchestrator resolves an ORCHESTRATOR-PAUSE by default, and promotes it to USER-PAUSE ONLY when genuine user attention is truly needed (the one exception: a prepass `auto_pause` entry with `resolutions` of 1 or more is a USER-PAUSE, see **repeat-count auto-pause**); promoting to avoid making a derivable call is the forbidden lazy-pause anti-pattern |
| **Recording propagated sites** | `how-to-fix.md`'s rule that every file touched while addressing a single finding is named in that same FIX's address (e.g. `FIX (foo.py + SKILL.md's relevant section + ...)`), never split into separately flagged fixes, unless a closure-reached site needs a genuinely different fix |
| **`description:`** | The SKILL.md frontmatter field `how-to-fix.md` falls back to for the target's documented intent when the target has no README `## Intent` section |
| **in-scope file** | A file `scripts/inscope.py` (`inscope_files`) selects under the target: everything except dotfiles and dot-directories, `__pycache__`, `_archive`, `.pyc`/`.pyo` and binary suffixes, `.bak` names, `-workspace` and `evals/iteration-*` paths, and README.md / HISTORY.md / LICENSE / LICENSE.* names; the set a full-sweep review lists and the coverage gate checks |
| **In-scope** | `agent-cold-code-review.md`'s boundary: claims in the listed files checked against the actual behaviour of any listed scripts and the actual content of any listed briefs — paired with Out-of-scope |
| **Out-of-scope** | `agent-cold-code-review.md`'s boundary: behaviour of the executor harness, the Agent tool, the file system, networking, the user's environment, and any file not listed in [SKILL_FILES] (unless the prompt's `## Scope` allows opening it as evidence); external-system concerns, not trace issues, unless the skill describes their absence as a guarded condition and the guard is broken |
| **Exact label form (load-bearing)** | `agent-cold-code-review.md`'s ISSUE-block formatting rule: each of the four lines must begin with the bare keyword immediately followed by a colon (`ISSUE [`, `File:`, `Claim:`, `Target:`) with nothing inserted between the keyword and its colon |
| **Cluster `guidance` field** | The optional one-line field an orchestrator attaches to a cluster in the cluster JSON after weighing the target's intent; when present, the fixer follows it as the primary steer for that cluster's fix |
| **round gate** | The mechanical stop rule evaluated after every non-converging `close-round` (and by `append_ledger.py gate`): it reads the persisted run options and stops the run with one of three reasons — `round-cap`, `budget-exhausted` or `stalled`. A round-gate stop is NOT convergence and is reported as "not verified clean"; it is the only cost control on a run |
| **round-cap** | The round-gate stop reason meaning this run has used its `max-rounds` allowance of rounds, counted from `run-start-round` |
| **budget-exhausted** | The round-gate stop reason meaning the round budget requested with `--rounds N` (persisted as `rounds-budget`) is complete |
| **stalled** | The round-gate stop reason meaning the last 3 closed rounds never beat the best earlier round's raw flag count, so fixes are not converging |
| **max-rounds** | The run option capping how many rounds one run may use before the round gate stops it with `round-cap`; default 8 |
| **fresh run** | A run that starts because skill-tracer was invoked this turn (by the user or proactively) while the ledger holds no open-round marker for the target and no `begin-round` has run since that invocation; only its first `begin-round` passes `--set` options, and the later rounds it starts in the same turn pass none. An open-round marker makes the invocation a resume instead; the test is SKILL.md's "Fresh run or resume" (Run options) |
| **Fresh run or resume** | SKILL.md's executable test (Run options) that decides whether an invocation sets run options: an *open-round marker* (an `in-flight::` line that is not `converged`, for a round with no `<!-- Round <N> total` summary comment) means a resume; no open-round marker plus an invocation this turn (by the user or proactively) with no `begin-round` run since it means a fresh run; otherwise (no invocation this turn, or a `begin-round` already run since it) it is the next round of the same run |
| **Resume** | Continuing the round an open-round marker names, after a compaction or on a new invocation (`references/recovery.md` "Resume"); it passes no `--set` to `begin-round`, and run options the user asks for meanwhile are merged with `append_ledger.py options --set` |
| **Retry bound** | SKILL.md's limit on the fixer re-emit, fixer re-dispatch, reviewer re-dispatch and post-fix gate inner-pass loops: at most 2 retries, then an ORCHESTRATOR-PAUSE (a hard unrecoverable error for a reviewer slot); the prepass re-fix of a returning finding gets 2 fixer passes per round and its next return is auto-paused; in code only the prepass loop counts it (`ledger_common.AUTO_PAUSE_REPEATS`). Contract recovery keeps its own limits |
| **run-start-round** | The run option recording the first round number of the current run, so the round gate counts only this run's rounds when a fresh run reuses a ledger that already holds earlier rounds |
| **rounds-budget** | The run option holding the round budget requested with `--rounds N`, persisted in `run-options`; the round gate reads it and stops the run with `budget-exhausted` once that many rounds are complete |
| **run-options** | The single ledger-header line `run-options:: rounds-budget=… max-rounds=… run-start-round=…` (format v2) that persists a run's budget, cap and first round so they survive a compaction; read and merged with `append_ledger.py options`. Legacy v1 `mode=` / `cr-mode=` keys are migrated on read (`references/recovery.md` "Persisted run options") |
| **close-round** | The `append_ledger.py close-round` subcommand that closes a round on the ledger (refusing while a pause is open or a row of the round is still PENDING) and reports the round gate's verdict; with `--converged` it writes the terminal `converged round-<N>` in-flight marker |
| **--strengthen-only** | The `append_ledger.py close-round` option, taking a reason string, that lets a round close with no FIX-kind row because every finding in it was a legitimate STRENGTHEN (one of the four cases in `references/how-to-fix.md` "Choose STRENGTHEN when"); the reason names that case. Without it (or `--converged`), `close-round` refuses a round that holds no FIX row |
| **Hard unrecoverable error** | A stop reason for the whole run, listed in `references/recovery.md` "Hard unrecoverable errors" (a broken ledger, a missing prerequisite, a crashed prepass detector, an aborted reviewer, a slot still invalid after contract recovery, an unrestorable out-of-target fixer Write, a reviewer slot that edits a file after its 2 re-dispatches); the orchestrator stops and tells the user instead of continuing or guessing |
| **Fix depth** | The every-round rule that the considered-fix decision and the fixer apply the deepest root fix that does not widen the interface (`references/how-to-fix.md` "Fix depth"), fixing every finding regardless of a "minor" label |
| **blast category** | One of the four kinds of site a FIX must also cover in the same round (fix-impact closure): shared convention / value / format (every producer and reader of a changed string, value or format), producer ↔ consumer (every consumer of a changed output, or the producer of a changed expectation), parallel call sites (every sibling instance of a corrected pattern), and cross-reference pointers (every pointer to a moved, renamed or deleted step, section, file or variable) |
| **Naming discipline** | The four rules a fix must follow when it introduces a new stable name: (1) no collision with ordinary prose — the name must not double as a common phrase used elsewhere with its plain meaning; (2) compositional honesty — a name built from an existing name must really mean that composition; (3) mandatory, standalone glossary entry — the name gets a self-contained row in this glossary; (4) check for an existing near-synonym first and align to it instead of adding a redundant row |
| **auto_pause** | The status-JSON array field, emitted alongside `"status":"needs-fix"` by `prepass_run.py`, listing every cluster the repeat-count auto-pause wrote as an open ORCHESTRATOR-PAUSE row instead of sending it to the fixer |
| **auto_touched** | The `fix_blast.py` blast-entry field listing the files the blast computation already counted as touched for a cluster (the cluster's own definition file); `ledger_cascade.py --mode fill-address` merges it with the fixer's `touched_files` before re-running `check_fix_radius.py`, so a fixer need not list those files itself |
| **aborted_agents** | The stderr JSON field `code_review_collect.py` emits (with exit 1) when one or more cold code-review agents aborted at the pre-flight gate because files in their staged file list do not exist; it lists the aborted agents. It is a hard unrecoverable error, not a format violation: no reformat `SendMessage` and no re-dispatch can repair it, so the orchestrator stops and reports the agents and missing paths to the user |
| **changed-scope review** | A code-review whose scope is only the in-scope files the previous round's and this round's ledger addresses name (the files the fixes touched); `code_review_run.py --scope auto` chooses it from round 3 of a run, except when those addresses name no in-scope file, where it chooses a full sweep. Its reviewers may open other target files as evidence, but each finding names a listed file |
| **changed-scope-clean** | The `code_review_collect.py` status for a clean changed-scope review; not convergence: the orchestrator re-runs `code_review_run.py --scope full` in the same round, and only a clean full sweep converges |
| **cr-scope record** | The file `<out-dir>/cr-scope-<N>-<RUN_TIMESTAMP>.json` (`{round, scope, reason, files}`) `code_review_run.py` writes and `code_review_collect.py` reads, so the coverage gate checks exactly the files the reviewers were given |
| **frozen interface** | The rule that from round 1 of a run a fix adds no CLI flag, mode, subcommand, file, ledger field, run-options key, row kind, shared helper module, doc section, or any other new interface element such as an output JSON field, status value or exit code; a fix that needs one becomes an ORCHESTRATOR-PAUSE unless it is the only way to fix a real behaviour bug, and a wrong comment or doc over correct behaviour is fixed in the comment or doc, not the code (`references/how-to-fix.md` "Frozen interface"). A fixer adds no new behaviour: a fix makes the doc match the code, or the code match its documented contract. Adding a retry, cap, branch or exit path, or removing a fallback, is new behaviour: apply no edit for that cluster and emit ORCHESTRATOR-PAUSE naming it. `assemble_fix_prompt.py` fills the fixer prompt's `[INTERFACE_RULE]` slot with it |
| **doc lint** | `scripts/doc_lint.py`, the fixed advisory lint run after a Code Review fixer: section and ordinal references, list counts, script-contract exit codes, docstring Usage flags, the glossary, retired terms (`RETIRED_TERMS`), docstring counts, undefined dollar-sign variables in prose, and in scripts fix-event narration in comments or docstrings, a docstring "Raises" with no raise in the function, and unused function parameters (twelve checks); it never gates |
| **advisory** | A finding that is reported for the orchestrator to judge and never gates a tier by itself (the `advisory` detector level and every `doc_lint.py` finding; `doc_lint.py` never exits 1); the post-fix gate separately reports a lint finding that is new or on a line a fixer touched as a `lint:<check>` problem, which blocks closing the round (see **post-fix gate**) |
| **Fixer dispatch** | SKILL.md's rule for running a fix: one edit-capable fixer agent per fixer batch, the batches dispatched one at a time in order, each pointed at its batch's staged fixer prompt with a provenance pointer and editing only files under the target |
| **fixer batch** | The clusters one fixer handles from one staged prompt: every cluster of a tier pass of 12 or fewer (`ledger_common.FIXER_BATCH_MAX_CLUSTERS`); above 12, the code clusters and the doc-only clusters are each chunked separately into batches of at most 12, code batches first, so a batch never mixes them and a short last code batch is not topped up (15 clusters, 2 code and 13 doc, give 2, 12, 1). `prepass_run.py` or `cluster_enforce.py` prints them as `batches` with each batch's cluster ids, model and staged prompt |
| **Decision check** | SKILL.md's step after each fixer returns: `scripts/check_decisions.py` reads the fixer's decisions and exits 1 on an empty address, a kind prefix that differs from the decision, banned dismissal vocabulary, a FIX without its Closure block, or a missing or foreign cluster; the orchestrator then sends the problems to the same fixer to re-emit, before fill-address, at most 2 times (SKILL.md "Retry bound"); after that the batch's transcript is left out of fill-address, which records its clusters as ORCHESTRATOR-PAUSE |
| **Fix-recording step** | The `ledger_cascade.py --mode fill-address` call that records a returned fixer's decisions into the round's PENDING rows (`--phase Prepass --reenter` or `--phase "Code Review"`) |
| **post-fix gate** | `scripts/post_fix_gate.py`: `snapshot` before each fixer batch and `check` after it; a check that exits 1 (a new or touched-line lint finding, a name on a touched line that does not resolve, a new raise/return/exit/branch node on a touched line, a touched .py file that no longer parses (kind `syntax`, line 0), a removed name still cited, or a rewritten block not re-read whole: kind `block-reread`, a doc block with at least 2 and 30% of its lines changed that no `Blocks:` closure line names, whose untouched lines are also lint- and name-checked) blocks closing the round (an orchestrator rule; `close-round` does not read the gate) until the same fixer clears it, at most 2 inner passes, then ORCHESTRATOR-PAUSE (SKILL.md "Post-fix gate") |
| **Closure block** | The `closure` list every FIX decision carries: four one-line strings, `Siblings:` (each other site naming the same claim, term, flag or step, as file:line updated or unchanged), `Bound:` (the limit, edge case and existing remedy of each loop, fallback, retry, error path or definition the fix added, or `none added`) `Claims:` (each factual sentence the fix wrote with the file:line proving it) and `Blocks:` (each paragraph, table or comment run the fix rewrote as `file:start-end`, re-read whole, or `none rewritten`; `post_fix_gate.py check --fixer-transcript` reads it); `check_decisions.py` exits 1 when one is absent or empty (`references/how-to-fix.md` "Closure block"). Not the same as fix-impact closure, the blast-radius coverage check |
| **siblings list** | The non-blocking `siblings` field of `post_fix_gate.py check` output: for each distinctive term on a touched doc line (a backticked span with an underscore, path, dot, dash, space, bracket, colon, equals sign, digit or capital, a CLI flag, a file name, or a quoted phrase of two or more words), up to 5 of the 1 to 12 untouched lines naming it, with their total, fewest first and at most 15 terms; `siblings_omitted` counts the terms left out as too common or beyond the cap; the orchestrator sends it to the fixer with the inner-pass problems |
| **new-behaviour** | The `kind` of a `post_fix_gate.py check` problem for a touched non-test .py file that gained a raise, return, exit, branch (`if`, `ifexp`, `boolop`), loop or try node on a touched line, named in the problem text as `<kind> count N -> M`; it is never fixed in an inner pass but goes straight to ORCHESTRATOR-PAUSE, because a fixer adds no new behaviour (frozen interface), even for a contract-required or real-bug fix (the check-pauses step resolves that pause; this gate outcome takes precedence over `references/how-to-fix.md`'s "never a fix-failure fallback"), unless the change is a behaviour-preserving refactor, which the orchestrator waives with `check --accept-new-behaviour <file>:<kind>`, where `<kind>` is that node kind (`raise`, `return`, `exit`, `if`, `for`, `while`, `try`, `ifexp` or `boolop`), not `new-behaviour`, and records in the ledger |
| **survival record** | The ledger comment `<!-- survival:: round N C<k> flags … cause=<cause> -->` that `post_fix_gate.py survival` writes under a row whose flag survived its round, with the cause `cascade` (the flag sits on text a previous fix of this run wrote or changed), else `badly-fixed` (the earlier fix touched the flagged line but the flaw stayed), else `not-merged` (the earlier fix was made only in an audited copy), else `never-found` (the earlier round's reviewers did not surface this flaw); kept out of the Flags cell so `close-round` and `verify-auditability` do not read it as flags |
| **merge-check** | The `post_fix_gate.py merge-check --source <src> --audited <copy>` comparison run at the end of a run, against the source copy the orchestrator finds itself (SKILL.md "Present result"); exit 1 lists the files where the two trees differ, so fixes made in the copy are not lost |
| **orch-fixes** | The in-flight-marker `<state>` (the third field of `<Runtime> <phase> <state> round-<N>`) meaning the last recorded fixer pass left an open ORCHESTRATOR-PAUSE; resolve it with `check-pauses` before re-running a tier script |
| **block-reread** | The `post_fix_gate.py check` problem kind for a rewritten doc block (3 or more lines, at least 2 and 30% of them changed) that no `Blocks:` closure line of a decision in `--fixer-transcript` names; clears when the fixer re-reads the whole block and lists it as `file:start-end` |
| **siblings_omitted** | The count, in `post_fix_gate.py check` output, of terms left out of the `siblings` list because they name more than 12 untouched lines or fall beyond the 15-term cap |
