# Audit checks (read-only; fixes proposed, confirmed one at a time)

Run `scripts/graph_audit.py PAGES_DIR --schema SCHEMA_CONFIG --relations assets/relation-vocabulary.json`. It reads only. It has no fix mode: Claude lists each finding with page and line, proposes the fix, and applies it by hand only after the user's yes for that one finding, then re-runs the same check on that page. (The safe-fix categories of the `fix` subcommand are different: they are applied together after one go-ahead on the pre-fix report.)

## Checks and codes
| Check | Codes | Meaning |
|---|---|---|
| properties | `missing-type` (error: no `type::` on a page that is not a template), `type-vocab`, `writer-vocab`, `status-vocab`, `required-properties`, `blank-title`, `zotero-only-property`, `template-writer`, `claude-on-notes` | Vocabulary lists and required properties come from the schema JSON, not from the script (fixed roles and template detection: rules Roles fixed in the format contract and Templates and the blank writer, `references/rules.md`). `claude-on-notes` is info: confirm Claude really wrote that page. |
| format | `yaml-frontmatter`, `md-heading`, `checkbox`, `image-embed`, `url-property` | Dual-format rules. Fenced code is skipped. |
| links | `bracketed-missing`, `plain-existing`, `dead-end-link`, `name-collision`, `self-alias`, `orphan`, hubs list | `bracketed-missing` (error): link-type property bracketed to a page that does not exist. `dead-end-link`: cited but never defined. Orphans and hubs are information. |
| mentions | `unlinked-mention` | A page title, filename or alias (5+ characters) appears in a page that does not link it. A candidate only: Claude reads the sentence to judge the sense before proposing a link. Never report a mention as an error on the title match alone. |
| relations | `relation-missing`, `relation-no-reason` | Links under a Connections heading must start with a vocabulary verb and give a reason after a colon. |
| placeholders | `placeholder`, `blank-writer` | Leftover template text: angle-bracket placeholders, the `{{title}}`, `{{date}}`, `{{citekey}}`, `{{module}}` and `{{name}}` variables, and TBD, FILL IN, INSERT HERE or PLACEHOLDER wording. A line holding one of the HTML tags br, hr, sup, sub, a, em, strong, code, p, ul or li is not reported for the angle-bracket pattern. Run on every page just written (read-back) as well as in audits. A leftover placeholder is a failed write. |
| stale | `stale`, `verified-date` | `stale`: `verified::` older than the limit (default 180 days); `verified-date` (warn): a `verified::` value that is not an ISO date. Not a learning schedule: it only surfaces pages to re-read, and only on request (`--checks stale`; the default run leaves it out). |

## Using it
- **Scope:** pass `--only-pages` for the pages touched (a `dead-end-link` or `name-collision` is reported on one page only, the first citing or colliding page, so a scoped run can miss it: run the full audit after creating pages that cite or rename things), `--exclude` with the page names the user gives as their drafts (comma-separated; the script matches names, so ask which pages are drafts rather than guessing from `type::`). Draft pages: rule Drafts (`references/rules.md`).
- **Read-back after writing:** rule Read-back after a write (`references/rules.md`).
- When the user asks for a weekly routine: the user schedules it with their own scheduler, and it runs this audit as a report only (rule Unattended run (weekly routine) in `references/rules.md`). Weekly report order: errors, warnings (dead-end links are warnings), orphans, hubs, then the remaining info findings; stale dates are left out of it. Nothing is changed by the routine.
- Judge by reading: codes and counts point where to look; Claude reads the page before proposing a fix. The script prints one line per finding, `page:line: [severity] code: message` (`--json` gives the same fields); Claude adds the proposed fix when it presents the findings.
- **Where the graph is:** resolve the graph and its schema through the registry (SKILL.md Step 0, resolve the graph), never a guessed path. The existing maintenance scripts (`schema-lint.py`, `graph-link-audit.py` and the rest) stay as they are and stay the way to audit and to apply safe fixes there (`graph-link-audit.py` and `schema-pass.py` write; `schema-lint.py` only reports); this script does not replace them. Which codes are the same defect as a `schema-lint.py` or `graph-link-audit.py` line, which take a safe-fix marking, and where the scripts disagree: rule Equivalent codes across scripts (`references/rules.md`). Which folders each script skips, what each reads (journals, drafts) and how code is treated: rule What each audit script reads. This script itself never writes; how a code is marked in the merged report (safe-fix or report-only) follows rule Equivalent codes across scripts.
